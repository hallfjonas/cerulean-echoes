## For the converter

- Performance only: `npm run producer -- <mid> --map <map> --perform` writes just `perform/<track>/<name>.json` from the
  map's `performance` (overwriting it), so the filled track and performance designs are never touched; no `--force`
  or `--out` detour. Added with a test; `npm run producer` added to `tools/package.json` (the usage line named it,
  the script was missing).
- A test now proves the 013 map regenerates the track text and `one-hope.json` exactly, as for 012.
- Chapters that keep the song's place cannot make a repeat: after a held chapter the next chapter (or Song) lands
  mid-section (Part 2 held twice → the song's place is bar 7, Part 3's bar 53). A classical repeat needs chapters
  that restart at their first bar (the song design's alternative); a map option for it would let the performance
  use Chapter musically.
- `defaultPerformance` plays the song twice with every fader ramped from 0 over 2 bars at bar 0: a part whose first
  note is at bar 0 (013's cello pedal) starts nearly silent (a note keeps the level it starts with). Parts that start
  at bar 0 should get their level set, not ramped; a song with a written ending wants one run plus a ring-out bar.
- `audibility` measures bars 1-4 only, where 013 has two parts: the other five stems show SILENT by the score.
  Mid-song levels need `strudel-sim/render.mjs <track> '<stems>.early(<bar>)' '<cc json>'` by hand; a `--from <bar>`
  option on audibility (and taking the state from a perform script) would make this a one-liner.
- The SSO sounds were missing from `samples/sounds.json` again (verify FAIL "not checked yet"); `check-sounds` added
  them (29 sounds, 0 broken). The producer could run it, or warn, after writing a track with new sounds.
