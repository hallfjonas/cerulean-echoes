# Epic: producer-mode-guitar-pro

## Overview

Three Guitar Pro songs (MIDI exports in this folder) become live tracks with an auto-performance. Order: a MIDI reader,
then the pilot (012 Slow Rock) designed and built by hand in two user loops, then a converter tool distilled from the
pilot, then 013 Classical and 014 EDM generated by the tool and refined with user feedback that flows back into it.

## Architecture Decisions

- **Reader first, converter later.** The pilot needs the MIDI notes as mini-notation from day one (1,600+ notes), so
  the reader and a per-bar note dump come first; layout, voicing and performance stay hand-made in the pilot so the
  tool encodes decisions the user approved, not guesses.
- **Song form, verbatim.** Each stem plays its part as written. Song position = cycle count since evaluation, looped
  at song end. Parts are stored per section (one pattern per marker range) so the track stays readable; bars become
  cycles (`.slow` per bar length).
- **Same layout as 007-010.** One file, `// @mode 16 Mode 1`, template `midi-layouts/templates/dual-lc.strudel`,
  `@shared` blocks synced with `npm run shared`, every controller optional. More than 7 parts → grouped per column
  (design decides).
- **Genre-fit voices**, not gm_* soundfonts: each part re-voiced with the project's synths and banks; GM drum notes →
  project drum sounds.
- **Mapping file holds decisions.** `<track>-map.json` beside the track: part → column / voice, sections, Chapter
  meaning, pickup handling. The converter reads it; re-running keeps the user's choices.
- **Script v2** from the auto-performances epic (title, sections) for every performance; sections = song markers.
- **Sources move to the track folder** (`tracks/<genre>/NNN-<name>/<name>.mid`); this epic folder is removed after merge.

## Technical Approach

### Frontend Components
- None new. Tracks appear in the player catalogue automatically (any genre folder, `@mode` tag); perform scripts are
  listed from `tools/trajectory/perform/<track>/`.

### Backend Services
- `tools/producer/midi-read.mjs`: format 0/1, running status, tempo, time signatures, markers, per-track notes with
  channels merged, positions in bars (pickup aware). `--dump` prints parts per bar as mini-notation.
- `tools/producer/make-track.mjs` (after the pilot): MIDI + map → track `.strudel`, design stub, perform script.
  `npm run producer`.

### Infrastructure
- `tracks/rock/012-slow-rock/`, `tracks/classical/013-hope-for-niklas/`, `tracks/edm/014-edm-snippet/`: track, `.mid`,
  map, design, `feedback.md`, generated sheet / syx.
- `tools/trajectory/perform/<track>/<name>.json`.
- CLAUDE.md (layout, live tracks, tools), `tools/trajectory/README.md`; `npm run path-lint` clean.

## Implementation Strategy

1. 001 reader + dump (no user gate). 002 pilot design (gate 1) can start in parallel from the marker / part summary.
2. 003 build 012, 004 its performance (needs auto-performances 001) — gate 2: listening rounds until approved.
3. 005 converter from the pilot; proven by reproducing 012.
4. 006 (013) and 007 (014): each runs design → generate → listen loops; both edit the converter, so one at a time.
5. 008 docs and a project skill `producer` capturing the loop.

Checks per track: `npm run verify -- <track>`, `npm run audibility -- <track>`, `check-sounds`, CPU (no drop-outs in
the player), then the user listens.
