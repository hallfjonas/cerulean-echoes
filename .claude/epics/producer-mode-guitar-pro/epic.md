# Epic: producer-mode-guitar-pro

## Overview

Two Guitar Pro songs (MIDI exports in this folder) become live tracks with an auto-performance, simplest first. Order:
a MIDI reader, then the pilot (012 EDM Snippet) designed and built by hand in two user loops, then a converter tool
distilled from the pilot, then 013 Classical generated by the tool and refined with user feedback that flows back into
it. Slow Rock (tempo change, pickup bar) waits for a follow-up epic; its file stays here until then.

## Architecture Decisions

- **Reader first, converter later.** The pilot needs the MIDI notes as mini-notation from day one, so the reader and a
  per-bar note dump come first; layout, voicing and performance stay hand-made in the pilot so the tool encodes
  decisions the user approved, not guesses.
- **Song form, verbatim.** Each stem plays its part as written, looped at song end. Parts are stored per section (one
  pattern per section) so the track stays readable; one bar = one cycle (`setcps(bpm / 60 / 4)`).
- **Song start = performance start.** Auto-perform today starts on the player's current cycle
  (`startBarOf(engine.cycle())` in `tools/trajectory/autoperform.mjs`), while the song's position follows the cycle
  count. The script's bar 0 must be the song's bar 1. Two ways, decided with the user in 003: (a) starting a
  performance restarts playback at cycle 0, (b) the track reads a song offset that auto-perform sets on start. (a) is
  smaller; check that 007-010 scripts still behave.
- **Same layout as 007-010.** One file, `// @mode 16 Mode 1`, template `midi-layouts/templates/dual-lc.strudel`,
  `@shared` blocks synced with `npm run shared`, every controller optional. More than 7 parts → grouped per column
  (Classical has 9; design decides). Launchkey knobs CC 31-38 keep their meaning.
- **Genre-fit voices**, not gm_* soundfonts: each part re-voiced with the project's synths and banks; a program change
  inside a part is a voice change at that bar; GM drum notes → project drum sounds.
- **Mapping file holds decisions.** `<track>-map.json` beside the track: part → column, voice per program, sections,
  Chapter meaning. The converter reads it; re-running keeps the user's choices.
- **Two designs, two feedback logs.** The song design (columns, voices, controls, sections) is
  `<track>-design.md` with rounds in the track folder's `feedback.md`. The performance follows the existing convention:
  `tools/trajectory/perform/<track>/<name>.md` after `design-template.md`, rounds in `perform/<track>/feedback.md`.
- **Script v2** (merged with the auto-performances epic): title, bars, mood, sections. Section bars count from 0;
  marker bar n → script bar n - 1.
- **Sources move to the track folder** (`tracks/<genre>/NNN-<name>/<name>.mid`); this epic folder is removed after merge.

## Technical Approach

### Frontend Components
- None new. Tracks appear in the player catalogue automatically (any genre folder, `@mode` tag); perform scripts are
  listed from `tools/trajectory/perform/<track>/`.
- Possibly the restart-on-perform change in `autoperform.mjs` (decision above).

### Backend Services
- `tools/producer/midi-read.mjs`: format 0/1, running status, tempo, time signatures, markers, program changes with
  bar, per-track notes with channels merged, positions in bars. `--dump` prints parts per bar as mini-notation.
- `tools/producer/make-track.mjs` (after the pilot): MIDI + map → track `.strudel`, design stub, perform script.
  `npm run producer`. A producing tool: if it joins the Tools page, tag it `produce` (produce-perform-split epic).

### Infrastructure
- `tracks/edm/012-edm-snippet/`, `tracks/classical/013-hope-for-niklas/`: track, `.mid`, map, design, `feedback.md`,
  generated sheet / syx.
- `tools/trajectory/perform/<track>/`: `<name>.json`, `<name>.md`, `feedback.md`.
- CLAUDE.md (layout, live tracks, tools), `tools/trajectory/README.md`; `npm run path-lint` clean.

## Implementation Strategy

1. 001 reader + dump (no user gate). 002 pilot design (gate 1) can start in parallel from the PRD source table.
2. 003 build 012, 004 its performance — gate 2: listening rounds until approved.
3. 005 converter from the pilot; proven by reproducing 012.
4. 006 (013 Classical): design → generate → listen loops; changes go into the converter or the map.
5. 007 docs and a project skill `producer` capturing the loop; Slow Rock handed to a follow-up epic.

Checks per track: `npm run verify -- <track>`, `npm run audibility -- <track>`, `check-sounds`, CPU (no drop-outs in
the player), then the user listens.
