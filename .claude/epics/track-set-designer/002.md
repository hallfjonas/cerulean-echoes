# Task: Launchkey rig

## Description
The Launchkey of a stem track as a JSON file instead of frame code, so the Track Designer can choose and edit keys,
knobs and pads, and a set can switch it between tracks.

## Acceptance Criteria
- [ ] Format `sc/launchkey/<name>.lk` (format 1, versions as files with `parent`, naming like stems), schema
      `sc/launchkey/lk.schema.json`: keys (sounds of `sc/lib/lkkeys.scd`, which knobs blend), mod wheel, knobs 1-8
      (label, about, targets with ranges or a named built-in: brightness, length, space, echo, pad fog), 16 pads
      (name, file or font + note, gain, rate, lane, once, envelope), lanes (orbit, room, echo)
- [ ] `check-stems` checks rigs (schema, files exist, fonts, labels) and the `launchkey` field of tracks
- [ ] `sc/lib/lkrig.scd`: rig → `lkNote`, `lkCtl`, `lkPadNames`, Launchkey stem entry, states, samples, `@lk` tag
      lines; `stemtrack.scd` reads `"launchkey"` (frame code keeps working for tracks without it)
- [ ] 009's Launchkey extracted into a rig; a copy of the 009 stem track with the rig matches the frame code over a
      Launchkey scenario (keys, every pad, every knob, Fog/Tension on the pads) with `tools/sc-port`; differences
      explained
- [ ] `npm run stems` lists rigs with "used by"
- [ ] Feature tests: rig loads and plays keys and a pad (`sc-test/run.scd`), check rules (`check-stems.test.mjs`)

## Technical Details
Start from `sc/tracks/009-house/009-house-frame.scd` (`lkCtl`, `lkNote`, `stems`, `samples`, the `@lk` lines). The
009 track file itself is not changed (non-destructive): the proof uses a new track file or a scenario override.
Whether 009 switches to the rig is the user's call after the proof.
