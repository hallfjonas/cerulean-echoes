# Task: Device spike

## Description
Answer the open DAW-mode questions on the devices before any engine code is built: one session with both LCs and the
Launchkey. Claude prepares the test phases, the player presses, Claude reads the log.

## Acceptance Criteria
- [ ] Knob feedback on a DAW page: a position sent to DAW In ch 16 moves the knob's value; the next turn continues
      from it (no jump)
- [ ] DAW Fader Pickup (ch 7 CC 70): its default, and whether it delays a fader; off if it does
- [ ] Which DAW page (Mixer = 1, Control = 2) the engine uses; Page ▲ / ▼ confirmed as Mode 1 / Mode 2 buttons
- [ ] Today's custom-mode colours of the bottom buttons and knob LEDs, per mode, as palette indices or RGB
- [ ] LED flash / pulse: possible or not (needed by phase 2 for "pending at the next bar")
- [ ] Mode alone, pressed and held without a bottom button: does the LC change or report anything?
- [ ] Mode + bottom button, then auto-return (CC 30 back at once): time until knobs answer again; LEDs and screen
      kept or lost; knob / fader moves made while Mode is held lost or sent later; how many presses are lost
- [ ] Shift + Mode in DAW mode: does the settings menu open; can it change encoder curve (CC 121) or global channel
      (CC 100)?
- [ ] Mode query (ch 8 CC 30): answered in DAW mode or not
- [ ] Second LC behaves the same
- [ ] Launchkey MK4 25 DAW mode survey: how to enable it, what reports on DAW Out (pads, buttons, knobs), pad LEDs,
      screen. Survey only, nothing changes for the Launchkey in this epic
- [ ] Results in `docs/reference/lcxl3-daw-mode.md` (section "Measured in DAW mode") and, for the Launchkey,
      `midi-layouts/devices.md`; FR choices that changed are noted in the PRD

## Technical Details
Extend `sc/tools/lcxl3-daw-test.scd` with the new phases (prompts on the LC's screen as now). The player app may keep
running; nothing in the engine changes.

## Dependencies
None. Device time with both LCs and the Launchkey.
