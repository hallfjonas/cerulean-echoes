# Task: Mode-press defence

## Description
The Mode button cannot be locked. Make an accidental Mode + bottom button press cost at most that one press (PRD FR7,
FR13).

## Acceptance Criteria
- [ ] The driver keeps the page each LC should be on; a mode report (ch 7 CC 30) of anything else is answered at once
      with CC 30 = that page, then the repaint from 004
- [ ] The custom-mode port (MIDI Out) stays read, so Custom Mode 1 / 2 keep the track playable while away
- [ ] Watchdog in the 2 s scan: queries the mode (ch 8 CC 30) and corrects it, if 001 showed the LC answers;
      otherwise left out and noted in the PRD
- [ ] Persistent settings (encoder curve CC 121, global channel CC 100) set on connect, if 001 showed a menu can
      change them in DAW mode
- [ ] An LC that stays off its page longer than one bar is shown in the player and on the other LC's screen
- [ ] Feature tests: a simulated mode report brings the page back and repaints; a stream of reports does not loop
- [ ] Checked on the device: Mode + bottom button during 018, the LC is back before the next bar, the track never
      stops
- [ ] Docs: load the two `.syx` modes into every custom slot (odd = Mode 1, even = Mode 2), cover Mode for gigs

## Technical Details
Guard against a loop if the device keeps reporting (for example while Mode is held): return once per report, not
on a timer.
