# Epic: auto-perform-steering

## Overview

One measurement layer, then two ways to steer with it. `meta.mjs` turns analysis frames into one record per bar
(energy, density, brightness, width, build, section). The player draws these as curves with the script's target
curve over them. A sweep tool measures, per track, what each continuous control does to the series
(`control-map.json`). With the map, a target curve becomes script steps (open loop, `npm run curve`) or is followed
live (closed loop, Steer switch). Pilot 010 `journey`; check on 009.

Order: measure → see → map → steer. Nothing steers what it cannot read.

## Architecture Decisions

- **One pure module for the series.** `meta.mjs` takes analysis frames plus the bar number and returns per-bar
  records; no DOM, no Node APIs, so the browser and the CLI run the same code (like `analyse.mjs`).
- **Light analysis mode.** `createAnalyser` gets an option to skip the pitch FFT (8192 points); meta needs bands,
  onsets and decorrelation only. Keeps the live tap cheap.
- **Fixed energy scale.** Energy is absolute, not normalised per track: loudness of the mix mapped from a fixed LUFS
  range to 0..1 (range calibrated once against `npm run audibility`), weighted with density. Weights are tuned on
  `journey` against the user's ranking of its sections, then frozen.
- **Section from controller state.** Chapter and Break are read from `midi.cc()` each bar, not guessed from audio.
- **Bar clock = engine cycle.** Live: `engine.cycle()`; offline: the render's cycle count. A record closes when the
  bar number changes.
- **Curve lives in the script.** Optional `curve.energy` in script v2, `[bar, value]` points, linear between them.
  No separate curve file.
- **Control map is a generated, committed file.** `perform/<track>/control-map.json`, small, regenerated by
  `npm run sweep`. It lists swept controls (CC, `@ctl` name, values, measured series per value) and a `steer` flag.
- **Loop owns continuous controls only.** Steering moves controls with `steer: true` (Tension, Fog, Thin, row 1/2,
  faders as the map decides). Chapter, Break, Pattern presses, keys and pads stay in the script.
- **Controller is a pure function.** `steer.mjs`: `(target, measured, controlState, map, held) → moves`. Unit-tested
  against a model built from the map; the player only wires it to the bar clock and `setAuto`.
- **Human wins by port, not by guess.** `midi.mjs` already stamps each CC value with a time per port. A new
  `humanMovedAt(number)` returns the last time a real (non-auto) port moved that CC; Steer holds that control for 8
  bars after it.
- **Offline render of a script.** A `render-script.mjs` in strudel-sim renders the whole master with the script's
  CC changes applied per tick (reuses `compile` / `valueChanges` from `autoperform.mjs` and the harness), optional bar
  window, output WAV or straight into `meta.mjs`.
- **Non-destructive.** `npm run curve` writes `<name>-curve.json`; it never edits the source script.

## Technical Approach

### Frontend Components (player, `tools/trajectory`)

- `tap.mjs` — stereo tap on the Strudel master output (ChannelSplitter → two AnalyserNodes, time-domain reads at the
  analysis frame rate). Shared with `recording-replay`; if that epic has landed, reuse its tap point.
- `meta.mjs` — per-bar records from frames; build slope over 4 bars.
- Curve view — canvas panel (toggle key and Settings entry): four series, target curve, section bands, bar marker,
  per-section gap table after a run. Reads records only.
- Steer switch in the auto-perform drawer; status box line: `Steer on · target 0.62 · now 0.55 · Tension ↑`.
- Performer change: while Steer is on, steps on steered CCs are skipped.

### Backend Services (Node CLIs in `tools/`)

- `trajectory/meta-file.mjs` (`npm run meta -- <audio | script.json> [--from bar] [--to bar] [--out f.jsonl]`).
- `strudel-sim/render-script.mjs` — whole-mix render of a script with time-varying CCs.
- `trajectory/sweep.mjs` (`npm run sweep -- <track> [--controls …] [--base '{…}'] [--bars n]`) → `control-map.json`.
- `trajectory/curve-to-script.mjs` (`npm run curve -- <script.json>`) → `<name>-curve.json`.
- `check-perform.mjs` — validates `curve`; `npm run verify` runs it as today.

### Infrastructure

- No server endpoints; everything is local files and CLIs. Player server unchanged except serving new modules.
- Heavy jobs (render-script, sweep) one at a time, progress printed, bar window for short test runs.

## Implementation Strategy

1. Spike the two unknowns first (task 1): offline whole-mix render with a script, and the live master tap with its
   CPU cost. Both decide the rest.
2. Measurement and its view before any steering; the user judges the energy curve by ear on `journey` (calibration
   gate). Steering is built only after the energy scale is frozen.
3. Map, then open loop (cheap, offline, testable), then closed loop (live).
4. Second track (009) last, as the generality check.

Risks and mitigations:
- *Loop chases noise* → smoothing over 2 bars, dead band, per-bar move limit; unit tests with a noisy model.
- *Energy number ≠ feel* → calibration gate with the user's ranking; weights frozen after it.
- *Offline render too slow* → bar windows; sweep renders short (4 bars per value) windows.
- *CPU dropouts from the tap* → light analysis mode, cost shown in the status box, measurement off by default.

## Success Criteria (Technical)

- `meta.mjs` deterministic: same render twice → identical records; unit tests pass.
- Live vs offline energy on `journey`: median |Δ| ≤ 0.05 per bar.
- Tap + meta cost < 5 % of a bar's time on the M2; no audible dropouts in a full `journey` run.
- Open loop: `journey-curve.json` within ±0.10 of the curve in ≥ 80 % of bars (corners ± 2 bars excluded).
- Closed loop on 010: ≥ 90 % of settled bars within ±0.08; no steered control reverses more than once per 4 bars.
- Human-held CC: no Steer value for that CC in the 8 bars after a human move (unit test + live check).
- 009 with the same curve, closed loop: ≥ 80 % of bars within ±0.10.
- `npm run verify` passes, including `curve` validation.
