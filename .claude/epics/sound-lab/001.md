# Task: Stem architecture and file format

## Description
Fix what a stem, a stem version, a track and a set are, and the files for stems and stem tracks. Write it down for
people and make it checkable.

## Acceptance Criteria
- [x] `docs/features/stems.md`: the stem (sample, patterns on button 1, knobs 1-3, fader, button 2 add-on), versions
      and `parent`, the naming rule `<sample>-<k1>-<k2>-<k3>-<b1>-<b2>.stem` (lowercase kebab-case, `-2` on
      collision), the stem contract, the metadata decisions (role list, genres, energy, tags incl. moods, harmony;
      no categories tree; "used by" computed), preliminary definitions of track and set
- [x] `sc/stems/stem.schema.json` and `sc/stems/track.schema.json` (format 1), sketches in `epic.md` as the start
- [x] `tools/stems/check-stems.mjs`: schema, file name matches sample + labels, referenced sample / code / add-on
      exist, labels follow the label rules (row 1 Brightness, row 2 Space, fader Level, button 1 Pattern, `about`
      about 50 characters); wired into `npm test` and `npm run verify`
- [x] Two hand-written example stems (one drum, one melodic) pass the check
- [x] Set file: definition in the doc only, no schema

## Technical Details
